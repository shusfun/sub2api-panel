# 0006 精密调度仪器舱架构与标准工程分层

## 背景
1. 随着业务功能持续扩展，原仓库根目录平铺了 60+ 个 `.go` 文件，单个业务文件超过千行，且前端 `web/src/` 与 `web/src/pages/` 下散落 30+ 个平铺页面（单文件最高达 2198 行），缺乏清晰的领域包与分层边界，难以支撑并行开发与自动化守卫。
2. 原界面在 `0003` 确立的浅灰/纯白大表风格与 57px 顶栏外壳在多工作台密集调度场景下仍显得割裂，同时「渠道巡检 / 官方渠道监控」「兑换码 / 优惠码」「模型广场 / 可用渠道」「站点公告 / 公告管理」存在多入口重复。

## 决定
- **后端标准 Go 工程分层**：
  - 仓库根目录仅保留 4 个薄入口文件：`main.go`（保留 `version`/`commit` ldflags 锚点）、`embed_dev.go`、`embed_release.go`（承载 `//go:embed web/dist`）及 `main_test.go`（承载 `TestArchGuard` 与 `README.md` 兼容入口）。
  - 业务与基础设施按单向依赖迁入 `internal/`：`internal/platform/`、`internal/issuer/`、`internal/cli/`、`internal/server/core/`、`internal/server/{auth,pool,users,billing,observe,system,router}/`、`internal/testkit/`。`internal/server/...` 严禁导入 `internal/issuer`，所有非测试业务 `.go` 文件受 `TestArchGuard` 强制约束 `<= 600` 行。
- **前端分层架构与导航收敛**：
  - 配置 `@/*` 路径别名指向 `web/src/*`，重组为 `entry/`、`app/`、`lib/`、`schemas/`、`ui/{primitives,icons,patterns,data,domain,charts,styles}/` 与 `features/{public,observe,pool,users,billing,workspace,system,dev}/`。`web/scripts/check-ui.mjs` 强制检查 `src/ui/` 禁止反向导入 `features/` 或 `app/`，且 `src/features/` 单个 `.tsx` 文件 `<= 600` 行。
  - 按 RC 零兼容策略收敛重复入口：合并渠道巡检与官方渠道监控至 `/channels/status`（删除 `/channels/monitor`）；合并兑换码、优惠码与子管理员发码至 `/admin/redeem`（删除 `/admin/promo-codes`）；合并模型广场与可用渠道至 `/model-plaza`（删除 `/channels/available`）；管理员侧栏统一使用 `/admin/announcements`（内置管理与阅读预览切换）。
- **「精密调度仪器舱（Precision Dispatch Desk）」公共 UI 体系**（取代 `0003` 的视觉配色与外壳，完整保留 `0003` 的公开认证闭环）：
  - 移除占满顶部的旧全局 Topbar；桌面端采用五档物理灰阶底座（亮色矿物石 `#e9e9e4` → 凹槽 `#e5e5df` → 舞台 `#f2f2ee` → 面板 `#fafaf7` → 浮层 `#ffffff`；暗色阳极石墨 `#0d0f12` → `#0e1014` → `#12151a` → `#181c23` → `#212730`），左侧栏集成品牌、⌘K 速跳槽、5 组精炼导航与底部身份/主题/退出控件，右侧以 `7px` 奇数内边距嵌入 `13px` 超椭圆（`corner-shape: squircle`）主舞台视窗与 `45px` 紧凑情境舱头 `StageHeader`。
  - 全站数值启用 `tabular-nums slashed-zero`，写死像素严格遵守奇数刻度，零常驻循环背景动效；补齐 `StageHeader`、`RouteChain`、`GeoExitBadge`、`IdentityBadge`、`CronField`、可排序表头及 `SortDirectionIcon`、`EnableMorphIcon`、`PlusCloseMorphIcon`、`FilterMorphIcon` 等单 SVG 连续形变图标。

## 考虑过的方案
- 保留根目录平铺 Go 文件仅拆分子文件：无法在编译期强制隔离 `issuer` 与 `server` 边界，也无法按领域清晰授权并发协作。放弃原因：包级物理边界显著优于文件命名约定。
- 为被收敛的旧路由保留前端重定向别名：违背项目 RC 阶段「改动直接替换旧实现，不做向后兼容」原则。放弃原因：直接清理旧路由并由 `TestArchGuard` 强制前后端 1:1 同步。

## 影响
- 所有前后端新增业务模块均受 `go test`（`TestArchGuard`）与 `pnpm --dir web check` 自动守护，防止单文件膨胀、跨层反向导入、偶数像素值与路由漂移。
- `0003` 标记为 `superseded` 保留存档，其公开首页与全链路认证功能继续在 `web/src/features/public/` 中运行。

## 依据
- 本次全仓基础架构与精密调度仪器舱设计系统升级任务决策。
