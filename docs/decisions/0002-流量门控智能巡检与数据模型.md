# 0002 流量门控智能巡检与领域数据模型

## 背景
传统渠道监控采用固定分钟/秒级轮询，在夜间或冷门分组无用户请求时持续空跑大模型推理，浪费大量上游 Token 与额度；同时网络抖动导致的请求报错若混入「降智」统计，会污染真实模型品质结论。面板需要一套按实际活跃用户数自适应唤醒的省 Token 巡检机制，并支持按需向登录用户或公开首页开放脱敏看板。

## 决定
- **权威数据**：
  - 实时流量信号以官方 Sub2API 只读库 `official/` 的 `usage_logs`（滑动窗口内 `COUNT(DISTINCT user_id)` 与请求数）为首选事实源；未配置 `PANEL_OFFICIAL_DATABASE_URL` 时回退官方 `/admin/ops/concurrency` 与 `/admin/ops/user-concurrency`。
  - 面板数据库（PostgreSQL + Ent）维护三类实体：`PatrolPolicy`（每分组巡检与门控策略）、`ProbeTemplate`（管理员自定义提示词与命中判据规则配置）、`PatrolRun`（只追加的每次巡检或免检事实记录）。
- **四档门控状态机**：
  - `skipped_idle`（低峰免检）：窗口内去重活跃用户数 `< min_active_users` 且请求数低于下限时，不发起任何上游模型请求（0 Token 消耗），写入一条免检记录并保留上一轮有效品质结论。
  - `ok` / `degraded`（有效品质判定）：活跃用户达标唤醒巡检，引擎执行成功并按指纹置信度、探针评分或自定义判据给出「不降智 (`ok`)」或「降智 (`degraded`)」。
  - `failed`（网络或通道失败）：超时、鉴权或上游 5xx 记录为失败，**严格排除在「不降智率」分母之外**；上一轮为 `degraded` 或 `failed` 时按短间隔触发快速复核。
  - 单日巡检累计消耗达到分组 `daily_token_limit` 或 `daily_budget_cents`（整数美分）时自动熔断，当日仅允许管理员手动触发。
- **版本、快照与冻结**：
  - `PatrolRun` 为只追加事件账本，创建时记录当次实际执行的引擎标识、模型名、推理强度、输入/输出/推理/缓存 Token、耗时与脱敏回答摘要；后续修改 `PatrolPolicy` 或 `ProbeTemplate` 不改写任何历史 `PatrolRun`。
- **保留期限**：
  - `PatrolRun` 默认保留 30 天（`retention_days`），由巡检后台协程按 `created_at` 索引定期清理过期记录，防止事件表无限膨胀；界面固定取每分组最近 60 条记录绘制健康柱状条。
- **失败与补偿**：
  - 单次巡检若使用短效临时 Key，在执行函数 `defer` 中立即吊销；进程启动及每轮巡检前扫描并回收带面板巡检前缀且已过期的残留临时分组/临时 Key。
- **明确不做的事与检查**：
  - 不在公开首页或普通用户巡检接口中返回内部 `account_id`、探测 Key、真实上游地址或原始报错体；通过独立响应投影结构体强制白名单过滤。
  - 不为报表往主表冗余累计字段；不降智率、平均耗时与节省 Token 均由最近窗口内的 `PatrolRun` 投影计算。

## 考虑过的方案
- 直接复用官方 `/admin/scheduled-test-plans` 或 `/admin/channel-monitors`：前者仅支持固定 Cron 且主通道写死 `"hi"`，后者为固定秒级轮询且无活跃用户门控与降智判定。放弃原因：无法按用户活跃度省 Token，也不支持多引擎指纹/黑盒验真。

## 影响
- `panel_serve` PostgreSQL 角色新增 `patrol_policies`、`probe_templates`、`patrol_runs` 读写权限；`panel_issuer` 权限保持不变。
- `official/schema/usage_log.go` 补充 `user_id`、`group_id`、`model`、`input_tokens`、`output_tokens` 只读列声明，不参与 `panel migrate`。

- 主人：「巡检页可以开给用户也可以不开，可以配置到首页去展示。」
