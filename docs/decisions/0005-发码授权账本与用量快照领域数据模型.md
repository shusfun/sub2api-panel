# 0005 发码授权账本与实时用量快照领域数据模型

## 背景
面板自有的 PostgreSQL 数据库承载两块核心自管状态：子管理员发码授权与幂等对账（`issuer` 进程独占）、以及未开启官方只读库直连时的实时用量分页观测与 SSE 游标恢复（`serve` 进程读写）。需要明确各表的权威来源、拉链版本策略与过期保留期限，避免观测缓存随自然日推移无限增长。

## 决定
- **权威数据与角色边界**：
  - `grants`（子管理员当前发码配额与 `epoch`）、`issues`（每次发码预扣、幂等操作号 `op`、上游码 ID 与退回状态）、`grant_audits`（只追加的额度变更审计）为发码领域的唯一权威来源，仅由 `panel_issuer` 角色读写。
  - `runtime_settings` 保存首次确认后的上游地址与加密的账号余额探测配置，由运行进程按需读取。
  - `usage_observations`、`usage_cursors`、`usage_snapshots`、`usage_versions` 为官方用量数据的派生观测缓存与 SSE 断线重连拉链版本表，仅由 `panel_serve` 读写，可随时从官方数据源重建。
- **状态机、版本与冻结**：
  - `issues` 按 `pending → issued | rejected | manual_resolved` 流转；预扣在事务内校验 `grant.epoch`，撤权递增 `epoch` 使旧周期异常单据不再退回新授权额度。
  - `usage_versions` 采用拉链表结构（`(scope, version)` 唯一、`valid_from` / `valid_to`、`fingerprint` 去重），仅当快照哈希实际变化时生成新版本，每个活跃 `scope` 最多保留最近 64 个版本供 SSE 游标做差量恢复。
- **保留期限**：
  - `grants`、`issues`、`grant_audits`、`runtime_settings` 永久保留，支撑额度核对与财务审计。
  - `usage_observations`、`usage_cursors`、`usage_snapshots`、`usage_versions` 与官方默认 90 天日志窗口对齐，设置 **95 天**保留上限（90 天查询窗口 + 5 天缓冲），由 `serve` 后台按采样/观测时间自动清理超期记录。
- **明确不做的事**：
  - 不在 `panel_serve` 中直接访问发码账本表，也不在业务代码中绕过 Ent 手写 SQL。

## 考虑过的方案
- 永久保留全部按日用量观测分区：查询窗口上限固定为 90 天，超过 95 天的观测缓存不会被任何接口命中，只会持续占用磁盘与索引。放弃原因：派生缓存必须设保留期限。

## 影响
- 全部早期 8 张 Ent Schema 补齐标准 6 行迁移说明头，快照 `payload` 收紧为强类型结构体，并在用量采样链路增加按小时节流的 95 天超期清理。
