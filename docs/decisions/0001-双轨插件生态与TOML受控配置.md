# 0001 双轨插件生态与 TOML 受控配置

## 背景
管理面板需要接入模型指纹检测（`Ikaleio/lm-detector`）、黑盒中转取证（`gpttest.xyz` / `gpt-relay-inspector`）、可选的访客自助检测以及后续社区工具。如果把所有外部探针、页面工具与题库写死进主仓库，不仅每次模型迭代都要维护题库并重新发版，还会在引入不同开源许可证（如 GPL）时污染面板自身的边界，也存在将长期凭据暴露给第三方站点的安全风险。

## 决定
- **采用「内置插件（`internal/pluginrt`）+ 类 Magpie 外部插件包（`internal/extplugin`）」双轨架构**：
  - 内置插件随二进制编译分发、按需启停、暴露声明式 `Settings`，关闭时零后台采样与内存开销。首发内置 `probe-lmfpd`（封装 `github.com/Ikaleio/lm-detector/sdk/go` 动态拉取并按 TTL 后台热更新模型参考指纹库）、`patrol-adaptive`（智能巡检调度与公开看板）与默认关闭的 `guest-self-check`（公开页访客自助检测）。
  - 外部插件支持独立市场清单 `registry.json`（内置精选种子 `gpt-relay-inspector`，支持 `PANEL_PLUGIN_MARKET` 或后台自定义仓库源同步）以及受控本地插件目录（`panel-plugin.json` 或 `package.json` 的 `sub2apiPanel` 字段）挂载与 `SHA256` 校验，社区可在独立仓库发布插件而无需修改主仓库。
- **配置与数据库分层**：
  - 插件启停、参数和市场清单保存在 `PANEL_DATA_DIR/managed/plugins.toml` 与 `ext-plugins.toml`，使用 `go-toml/v2` 强制校验 `schema = 1` 并拒绝未知字段。
  - 业务数据库读写继续统一使用 PostgreSQL + Ent，不引入 SQLite 或手写 SQL。
- **四类标准插件扩展槽与凭据测完即焚**：
  1. `probes`（探针与验号引擎）：自动注册进 `accounts` 测试连接与分组定时巡检选择器。宿主在当次调用期自动签发 **10 分钟过期 + 小额配额上限的临时网关 Key**（单账号深测自动建临时单号隔离组），调用结束 `defer` 立即吊销回收，插件全程拿不到管理员令牌或上游账号凭据。
  2. `pages`（隔离沙箱页面 + `_panel/bridge.js`）：运行于 `<iframe sandbox="allow-scripts">` 不透明源沙箱，注入只读冻结的 `window.sub2apiPanel` 自动同步当前亮暗主题、`--weir-*` 设计变量及 `permissions` 白名单声明的只读 `postMessage` 能力，可挂载至公开首页区块、侧栏或巡检页。
  3. `actions`（跨页面上下文快捷动作）：向 `account`、`group`、`key`、`ops-error` 注册上下文动作。
  4. `tools`（受控调用与审计）：统一经管理端 `/api/admin/plugins/{id}/invoke` 纳入权限校验与 `X-Request-ID` 追踪。

## 考虑过的方案
- 在面板内维护静态测试题库：新模型发布后题库迅速过时，维护成本高。放弃原因：直接对接 `lm-detector` SDK 热更新参考库与 `gpttest` SSE 接口加管理员自定义模板可实现零题库维护。
- 将长期网关 Key 或上游明文凭据交由前端直发第三方检测站：存在第三方日志留存密钥与越权消耗风险。放弃原因：违反服务端凭据边界，改用服务端短时限额临时 Key 测完即焚。

## 影响
- 新增可选环境变量 `PANEL_DATA_DIR`（默认 `./data`）与 `PANEL_PLUGIN_MARKET` 存放插件 TOML 状态、指纹缓存和外部插件包。
- 后台新增「插件」治理工作台，并在上游开启 `plugin_management_enabled` 时分区展示上游网关内核插件。
