# 0003 全站低饱和石板视觉与完整公开认证闭环

## 背景
原面板前端未提供公开首页、注册页、找回密码及第三方登录闭环，未登录访问直接落入极简登录卡片并通过外链跳往官方站点注册；同时原界面使用高饱和系统蓝与分散小卡片，与期望的克制、高信息密度控制台风格存在差距。

## 决定
- **全站视觉切换为低饱和石板体系（参考 `manxue.supeai.cc`，支持明暗双主题）**：
  - 在 `web/src/ui/styles/tokens.css` 统一重定义三层变量：明亮主题采用清透微暖浅灰画布 `#f7f7f6`、纯白表面 `#ffffff`、细描边与深石板炭黑主操作色 `#2d3139`；暗色主题采用深石板灰阶分层；链接与焦点环采用低饱和钢蓝；成功/警告/故障/信息统一采用低饱和语义色。
  - 严格保持奇数 `px` 刻度、`corner-shape: squircle` 超椭圆圆角、单容器半高竖线分隔的 `MetricStrip` 与 60 格 `QualitySparkBars`，全量弹性/网格子容器落实 `min-width: 0` 与长文本防溢出。
- **补齐完整公开首页与全链路认证（UX 对齐官方 Sub2API，会话由面板加密收口）**：
  - 删除旧极简登录页 `web/src/pages/login.tsx` 及外跳官方登录/注册链接，不做旧版并存。
  - 落地公开首页 `/`（支持 `home_content` 自定义页、`compact_home_enabled` 简洁页、标准落地页及内嵌公开巡检看板/首页插件槽）。
  - 落地完整认证页（`/login`、`/register`、`/email-verify`、`/forgot-password`、`/reset-password`、`/auth/callback`）：支持邮箱密码、邮箱后缀白名单、邀请码与优惠码实时校验、`?aff=` 返利码带入、6 位邮箱验证码倒计时重发、登录协议弹窗/勾选、三家验证码（Turnstile/腾讯/阿里云）、TOTP 二步验证、Passkey WebAuthn 登录（`begin/finish`）及全部 6 类第三方 OAuth（LinuxDo、GitHub、Google、微信、钉钉、OIDC）启动、回调换票与 `pending` 首次补全。
  - 所有认证出口统一经服务端 `startSession` 密封进内存加密会话（`__Host-sub2api-panel` HttpOnly Cookie），官方令牌不落浏览器存储。

## 考虑过的方案
- 继续将注册、找回密码与第三方 OAuth 外跳至官方前端域名：用户需要在两个独立站点重复登录，体验割裂且无法保持统一视觉主题。放弃原因：面板已具备完整的站点与安全配置目录，闭环接管公开入口体验更完整。

## 影响
- `panel.go` 与 `preview_vite_test.go` 支持公开路由的 `index.html` SPA 文档回退，确保邮件重置链接、邀请返利链接与 OAuth 回调地址直达可用。
- 更新 `docs/sub2api-compatibility.md` 与 `README.md` 中关于注册入口的描述。
