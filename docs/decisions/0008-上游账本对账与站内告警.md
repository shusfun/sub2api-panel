# 0008 上游账本对账与站内告警

## 背景
面板接入的上游账号（Sub2API、New API、One API 等）各自按美元或额度计费。需要把本站按官方 `usage_logs` 记下的收入与预计花费，同上游真实扣费对账，并在偏差、余额见底、采样失败时给出站内告警。官方 `usage_logs` 默认 90 天后清理，已封口的小时数据必须落在面板自己的库里。

## 决定
- **口径**：
  - 本站侧按官方只读库 `usage_logs` 按账号、小时桶、`billing_type` 聚合。收入为 `SUM(actual_cost) WHERE billing_type = 0`。预计花费为 `SUM(COALESCE(account_stats_cost, total_cost) × COALESCE(account_rate_multiplier, 1))`，拆为余额请求成本与订阅消耗成本两列，与上游 `usage_log_repo_stats.go` 的算法一致。
  - 未接官方只读库时退回上游管理接口，只能按天算，界面标注“按天”。
  - 小时桶按 `PANEL_USAGE_TIMEZONE` 切分，每 10 分钟重算最近 3 小时并 upsert，已封口的小时不再重算。
  - 上游侧每次采样记一条快照：余额、Key 累计已用、钱包累计已用、倍率。额度按 `/api/status` 的 `quota_per_unit` 换算成美元。
- **表**：
  - `ledger_wallets`：钱包身份（Key 的 HMAC 指纹，或“站点 + 上游用户 ID”的指纹）与折算单位，永久保留。
  - `ledger_accounts`：账号与钱包归属及名称、平台快照，账号删除只写 `deleted_at`，永久保留。
  - `ledger_samples`：采样快照，余额、累计已用、倍率都没变的采样只更新 `last_seen`，默认保留 30 天。
  - `ledger_events`：充值、推断充值、人工调整、退款、额度上调、基线重置事件，`(wallet_id, external_id)` 联合唯一，永久保留，作废只改状态。
  - `ledger_hours`：账号小时汇总，默认保留 365 天。
  - `ledger_days`：账号日汇总，永久保留。
  - `ledger_alerts`：站内告警，同一账号同一类型只允许一条处于 `open`（部分唯一索引），已恢复的保留 90 天。
  - 账本设置存于 `runtime_settings` 的 `ledger_settings` 键：`show_profit`、`deviation_pct`（10）、`deviation_min_usd`（1）、`runway_hours`（24）、`failure_threshold`（3）、`hour_retention_days`（365）、`sample_retention_days`（30）。
- **算账规则**（纯函数，集中在 `ledger_compute.go`，表驱动测试）：
  - 实际花费为两次采样间“累计已用”的正差值。
  - 差值为负记 `baseline_reset`，这一段用“余额变化 + 期间充值”兜底。钱包下有多把 Key 时改用预计花费并标记估算。
  - 一段采样区间的实际花费，按区间内各小时预计花费的比例摊到小时桶，预计花费为 0 时按时长摊。
  - 推断充值等于余额增加量加同钱包各 Key 同期花费，超过 0.01 美元才记 `recharge_inferred`。Key 额度上限变大记 `quota_raised`。
  - 余额降幅明显大于花费时记 `shared_wallet_suspect`，之后该钱包不再自动推断充值，改为待管理员确认。
  - 偏差等于实际花费减预计花费，毛利等于收入减实际花费，缺实际花费的小时用预计花费代替并标记估算。
- **告警**：类型为 `deviation`、`multiplier_change`、`runway`、`sample_failure`、`shared_wallet_suspect`、`low_balance`、`billing_missing`。条件成立时开启，条件消失时自动恢复，已有 `open` 时不重复开启。
- **采样与凭据**：
  - 扩展现有 `BalanceMonitor`，新增 `newapi`、`oneapi` provider，配置新增 `access_token` 与 `upstream_user_id`，并把加密抽成 `sealSecret` / `openSecret`，不另起第二套加密。
  - 采样沿用公网地址限制与 https 要求，采样成功与失败通过回调交给账本模块。
  - 访问令牌与 Key 只加密存放在服务端，接口只回 `configured` 标记。
  - Sub2API 账号详情只返回 `has_api_key`，不返回明文，所以 `api_key_from_account` 目前恒为 false。只有需要官方二次验证的导出接口带明文，后台采样与表单预填都不走它。
- **接口**：全部要求管理员，响应使用字段白名单结构体（`ledger_types.go`）。
- **探测**：`POST /api/admin/ledger/probe` 只收 `url`，用公开字段识别 New API、One API 或 Sub2API，识别不出时返回对方首页。

## 考虑过的方案
- 只靠上游余额差值对账：充值、共用钱包与基线重置都会被误判为花费。放弃原因：需要事件表单独记录充值与调整。
- 在 `usage_logs` 清理后重算历史小时：官方数据已不存在。放弃原因：封口小时只落库，不再重算。
- 手写 SQL 聚合：违反 Ent 唯一访问层规则。放弃原因：按分桶用 Ent 聚合，参照 `observe/official_stats.go`。

## 影响
- `official/schema/usage_log.go` 新增 `total_cost`、`account_rate_multiplier`、`account_stats_cost`、`billing_type`、`duration_ms` 五列只读声明，不参与 `panel migrate`。
- 需要执行 `panel migrate` 创建七张新表。
- 官方用量清理任务会让“本站侧”无法重算已清理时段，界面需提示。
