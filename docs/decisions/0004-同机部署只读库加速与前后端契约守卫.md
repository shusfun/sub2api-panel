# 0004 同机部署只读库加速与前后端契约守卫

## 背景
新版面板与官方 Sub2API 实例同机部署，已具备服务端回环访问官方管理接口与可选只读连接官方 PostgreSQL（`PANEL_OFFICIAL_DATABASE_URL`、`official/` 独立 Ent 包）的条件。早期部分接口按「跨网不可信外部客户端」假设实现，例如将官方网关插件配置裁剪成仅返回字段数量导致管理员只能盲贴 JSON 覆盖、按每页 100 条轮询 HTTP 搬运日志计算模型分时趋势、跨表记录丢失用户邮箱标识；同时面板内部的字段级报错、敏感操作二次验证字段名（`totp` 与 `totp_code` 混用）以及面向 Agent 持续开发的机械化架构守卫尚不统一。

## 决定
- **充分利用同机部署与只读库 `official/`，所有写入仍走官方 API**：
  - **网关插件配置脱敏回显与合并保存**：服务端读取官方 `/api/v1/admin/plugins/{id}/config` 后识别字段类型；对含 `secret`/`key`/`token`/`password`/`credential` 的敏感字段仅返回 `configured` 状态而不下发明文，其余字段按类型回显；保存时由服务端拉取现行配置合并未修改的敏感字段后再写回官方接口。
  - **模型分时趋势直查与实体标识补全**：配置 `PANEL_OFFICIAL_DATABASE_URL` 时，用量看板的模型分时序列直接通过 `official/` 只读聚合 `usage_logs`，未配置时回退 HTTP 分页观测缓存；优惠码使用记录等仅含 `user_id` 的列表优先经 `official/` `users` 表批量补全邮箱标识。
- **统一面板 HTTP 错误模型与敏感操作二次验证（RC 零兼容替换）**：
  - 面板错误响应在 `{code, hint, request_id}` 基础上支持可选白名单字段映射 `fields?: map[string]string`（仅限面板自身中文提示，严禁透传上游原始报错文本），并区分 `409 conflict`，直连前端 `Form.errors`。
  - 删除面板请求体中的 `totp_code` 异名字段，全站敏感写接口统一接收 `totp`，服务端在转发上游时按上游协议映射；`/api/session` 直接返回 `step_up_enabled` 与 `totp_enabled`，删除 `/api/admin/backups/permissions` 独立探测路由。
- **业务级 Trace 与双端 Agent 静态守卫**：
  - `transport.go` 提供绑定中文业务操作名、源码相对路径/函数名与构建提交号的 `startFlow` / `backgroundFlow`，并为巡检、采样、余额探测后台协程生成每轮根 `trace_id`。
  - 后端新增 `arch_guard_test.go`（`go/ast` 检查数据库连接边界、Ent Schema 6 行说明头、响应结构体类型安全、前后端路由同步与 `totp` 字段命名），与前端 `check-ui.mjs` 共同构成 Agent 自动化红线。

## 考虑过的方案
- 将网关插件配置保持只写不读：管理员修改单个非敏感开关时也必须手写完整 JSON 并重新填写全部密钥，极易误覆盖生产配置。放弃原因：同机部署下服务端完全可信，掩码回显加服务端合并既守住凭据边界又消除盲填。
- 同时保留 `totp` 与 `totp_code` 双字段兼容读取：项目处于 RC 阶段，保留别名会让后续 Agent 继续复制不一致命名。放弃原因：违反项目零兼容规则。

## 影响
- `official/schema/` 新增只读列与 `users` 只读表声明（不参与 `panel migrate`）。
- 前后端敏感验证请求、网关插件配置组件与测试夹具同步切换至新契约。

## 依据
- 主人：「做过决策的呀，要利用能利用的一切东西，新面板和源站是部署到一起的。」
- 主人：「符合项目架构，不兼容，代码架构适合agent开发，前后端不符合规范的都要改掉」
